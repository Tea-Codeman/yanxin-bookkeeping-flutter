> 验收对象：零配置新用户「第一次打开 App → 记下第一笔账 → 在首页 / 报表看到这笔账被正确归集」

## 4. 问题清单（按影响排序）

### P1（F1）报表页不随写操作刷新 —— 新用户记完第一笔，报表还是空的

- **影响等级**：阻断
- **证据等级**：设计推断（链路逐行核实；「`refresh()` 全库零调用」为 grep 已观察事实）。**UI 未实走**（环境阻塞）
- **维度**：D6 结果可取用 / D3 状态保留
- **用户处境**：零配置新用户第一次打开 → 先点「报表」探路（空态）→ 顺着空态按钮记了第一笔
- **操作**：报表页空态点「去记一笔」→ 记 ¥33.50 → 保存 → 自动返回报表页
- **看到的反馈**：仍是「这个月还没有记账」，三个档位全空（翻月再翻回来、或切档位才会出现）
- **为什么会卡住**：`reportsProvider` 是**常驻** provider（`reports_controller.dart:123`，非 autoDispose），`/record` 是 push 在报表页**上面**的 → 报表页 State 与 provider 都存活，不会重建。而 `ReportsController.refresh()` 的注释写着「记一笔 / 删除后刷新用」，**全库却零调用**；5 个写点（`record_page.dart:218-223`、`home_page.dart:116-120`、`calendar_page.dart:105-109`、`import_page.dart:145-149`、`search_overlay.dart:128-133`）都只刷 ledger / calendar / stats + bump 版本号，报表不在名单里。
- **最小修改**：`reports_controller.dart` 的 `build()` 里 `ref.listen(dataEpochProvider, …) → refresh()`（1 处，覆盖全部写点，且保留用户档位 / 月份）。**未用 `watch`** —— `watch` 会让 build 重跑并把月份 / 档位重置回「当月 + 明细」，等于吞掉 SPEC §A.2「报表页独立记月份」。
- **可观察的验收结果**：空态 →「去记一笔」→ 保存 → **直接看到**明细档里那笔流水；分类档出现「餐饮 33.50」。
- **状态**：**已实施**（`bd65f21` 之后的工作区改动）+ 2 例新测试；`flutter analyze` 等效门禁 `No issues found!` 通过；**UI 未验证**。

### P2（F2）首页两个报表入口不带月份 → 报表落到「它自己记得的月份」

- **影响等级**：卡住
- **证据等级**：设计推断（逐行核实）
- **维度**：D3 状态保留
- **用户处境**：用户在报表页翻到 8 月看过一次（或把首页 hero 翻到 8 月）
- **操作**：回首页 → 点「全部账单 ›」
- **看到的反馈**：报表页停在上次那个月份（`‹ 2025年8月 ›`），看不到刚刚在首页看到的当月数据
- **为什么会卡住**：`home_page.dart:174-177 / 202-205` 只传 `tab`，不传 `year/month`；`_apply`（`reports_controller.dart:202-205`）对缺省值取 `current.year/month`，而 provider 常驻 → 跨访问保留。日历页与月份选择页的入口都显式带了自己页面的年月，只有首页没带。
- **最小修改**：首页两处入口带上当前 `year/month`（`_Header` 需改 `ConsumerWidget` 读 ledger state；`_SectionHeader` 加两个参数）。
- **可观察的验收结果**：首页 hero 停在 8 月时点「全部账单」→ 报表也是 8 月。
- **状态**：**待裁定** —— SPEC §A.2.3 只对日历页 / 月份选择页写了「月份对齐」，首页那两条没写。属签字记录的空白，不擅自改。

### P3（F3）加载失败直出异常字符串，且没有重试

- **影响等级**：反馈不可懂
- **证据等级**：已观察（原文取自代码）
- **维度**：D5 失败可懂
- **用户处境**：首次打开时数据库起不来（native 库缺失 / 磁盘满 / 文件损坏）
- **操作**：打开 App
- **看到的反馈**：`加载失败：SqliteException(14): unable to open database file`（8 处同一写法：`book_manage_page.dart:40`、`calendar_page.dart:47`、`category_manage_page.dart:64`、`home_page.dart:51`、`book_drawer.dart:44`、`reports_page.dart:63`、`search_overlay.dart:182`、`stats_page.dart:32`）
- **为什么会卡住**：没有一句人话说明「发生了什么」，也没有重试入口 —— 用户唯一的动作是杀进程重开，且大概率同样失败。
- **最小修改**：抽一个 `LoadFailure`（图标 +「数据加载失败，请重试」+ 重试按钮 → `ref.invalidate(对应 provider)`），**先接核心任务路径的 2 处**（首页 `home_page.dart:51`、报表页 `reports_page.dart:63`），其余页登记 backlog。
- **可观察的验收结果**：DB 打不开时首页显示人话 + 可点的「重试」，点完恢复。
- **状态**：待办（未实施：涉及 8 处与一个新组件，超出「最小改动」）

### P4（F4）「设置」副标题承诺了三项可调，整行却点不动

- **影响等级**：体验摩擦
- **证据等级**：已观察（原文取自代码）
- **维度**：D1 入口可懂
- **用户处境**：想改默认账户 / 货币单位的用户
- **操作**：「我的」→ 看「设置」行
- **看到的反馈**：副标题「主题、默认账户、货币单位」，右侧灰字「建设中」，整行 60% 透明不可点
- **为什么会卡住**：副标题把未实现的能力写成了已完成的样子，用户会先尝试点击再放弃。
- **最小修改**：副标题改成「主题、默认账户、货币单位（未实现）」或换成已实现内容的描述。
- **可观察的验收结果**：读一行就知道现在能不能改。
- **状态**：待办（纯文案，1 行）

### P5（F5）入口叫「全部账单」，落地页标题叫「报表」

- **影响等级**：体验摩擦
- **证据等级**：已观察（原文取自代码）
- **维度**：D1 入口可懂
- **用户处境**：点「全部账单 ›」想看本月全部流水
- **操作**：首页「本月账单」区头右侧 →「全部账单 ›」
- **看到的反馈**：AppBar 标题「报表」，顶部还多出「明细 / 分类 / 账户」三个档位
- **为什么会卡住**：同一对象两个名字，用户需要自己完成「全部账单 = 报表的明细档」这一步映射。
- **最小修改**：`reports_page.dart:55` 的 AppBar 标题随档位变化（明细档「本月账单」）。**SPEC §A.2.3 明确要求入口文案保持，故未改**。
- **可观察的验收结果**：点「全部账单」后标题与入口同名。
- **状态**：待裁定

### P6（F6）记一笔页按返回即丢输入，无二次确认

- **影响等级**：体验摩擦
- **证据等级**：设计推断
- **维度**：D3 状态保留
- **用户处境**：输好金额和备注，误触返回 / 手势返回
- **操作**：在记一笔页点左上返回
- **看到的反馈**：直接回上一页，金额 / 分类 / 备注全部丢弃（无 `PopScope`、无草稿）
- **为什么会卡住**：输入成本不高（键盘敲数字），但与「已填内容不丢」的期望相悖。
- **最小修改**：`record_page.dart` 加 `PopScope`：仅当已输金额或备注时二次确认「放弃这笔记录？」
- **可观察的验收结果**：有输入时返回会先问一次；空表单直接返回不打扰。
- **状态**：待办（建议随 F3 一起排，避免连续两次小改动）

## 5. 认可已有设计

- **零配置即开工**：冷启动自动建「默认账本」+ 1 个现金账户 + 15 个预置分类（探针实测 100ms），A 类前置为 0 —— 这是本 App 最值钱的一条。
- **空态给出两条明路且指路精确到菜单层级**：「记一笔」按钮 +「已有微信 / 支付宝账单？到「我的 → 导入账单」一键导入」。
- **报表空态顺手解释术语**：「记一笔后这里会按明细 / 分类 / 账户分别列出」—— 把三档含义放在用户第一次见到它们的地方。
- **口径同源**：报表与首页 / 日历 / 统计共用同一句 `listByMonth`，转账不计收支在报表与统计两处都写明，用户对不上账的概率降到最低。
- **金额一律整数分**、列表按本地日分组、日标签与日历页逐字一致（`reportDayLabel`）。
- **不能翻到未来月**：首页 / 报表的「下一月」在当月自动禁用变灰。
- **明细档组头带笔数与当日支出合计**，分类档带占比条，账户档一行给出支出 / 收入 / 转账 / 笔数。
- **写操作后用「数据版本号」统一触发重算**（`data_epoch.dart`）：重算成本只写在消费方一处，F1 的修复正是接上这条既有机制。
