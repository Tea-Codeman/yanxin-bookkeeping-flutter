## 5. 问题清单（按影响排序）

### P1【阻断】导入成功但首页看不到任何数据，且无任何引导

- **维度**：D6 结果可取用
- **证据等级**：已观察（步骤 9–11）
- **用户处境**：零配置新用户，刚导入 327 笔微信账单（数据属于 2026-07）
- **操作**：我的 → 导入账单 → 选文件 → 确认导入（327 笔）→ 点「好的」
- **看到的反馈**：回到「我的」页；手动切回首页后，仍是「9月 · 支出 88.88」，列表只有「今天 / 餐饮 / -88.88」。刚导入的 327 笔**一个都看不到**，页面也没有任何"去看看"或"数据在某月"的提示。
- **为什么会卡住**：首页默认展示当前月（9月），导入数据落在 7月。用户既不知道要翻月，也没有跳转到结果月份的入口。用户会判定"导入失败了"。
- **最小修改**：`lib/features/import/presentation/import_page.dart` 的报告对话框，把单个「好的」拆成两个动作：
  - 主按钮「去看账单」→ `context.go('/')` 并把首页月份切到**导入数据的最早/最晚月份**（`LedgerController` 已有 `‹ ›` 翻月能力，加一个 `jumpToMonth(DateTime)` 即可）；
  - 次按钮「完成」→ 保持现状。
  - 报告正文补一行：`其中 327 笔属于 2026-07`。
- **可观察的验收结果**：导入完成后点「去看账单」，直接落在 7 月首页，hero 显示 417.92，列表首条为导入流水。

### P2【阻断】预算卡是硬编码假数据，与同一屏的真实 hero 数字矛盾

- **维度**：D6 结果有效 / 反馈不可懂
- **证据等级**：已观察（步骤 1、4）
- **用户处境**：零配置新用户，首屏
- **操作**：冷启动看首页；再记一笔 88.88 后回首页
- **看到的反馈**：
  - hero：「9月 · 支出 0.00 / 收入 0.00 / 结余 0.00」
  - 同屏预算卡：「本月预算 1,000.00 / 10.2% / 101.52 已消费 / 898.48 剩余额度 / 本月日均消费 10.15 / 剩余每日可消费 42.78」
  - 记一笔 88.88 后：hero 变 `88.88`，预算卡**纹丝不动**，仍是 `101.52 已消费`、`10.2%`。
- **为什么会卡住**：同一屏出现两个互相矛盾的"本月支出"数字。用户要么以为 App 算错，要么以为自己早就有 101.52 的历史消费。对记账 App 而言这是信任级问题。
- **根因**：`lib/features/ledger/presentation/widgets/budget_card_placeholder.dart` 全量硬编码（`1,000.00`、`value: 0.102`、`101.52`、`898.48`、`10.15`、`42.78`）。
- **最小修改**（二选一，优先 a）：
  - a. 预算功能未做前，卡片顶部加一行灰色小字「预算功能建设中，以下为示例数据」，并把「已消费 / 日均消费 / 剩余每日可消费」三处数字替换为 `—`（保留视觉骨架）。
  - b. 接真实数据：已消费 = 本月支出（hero 已有），日均 = 本月支出 / 已过天数，预算 1,000.00 保留为默认值并可点编辑。
- **可观察的验收结果**：首页不再出现与 hero 矛盾的支出数字。

### P3【反馈不可懂】二次导入报告「导入完成 / 成功导入 0 笔」自相矛盾

- **维度**：D5 失败可懂 / D6 结果可懂
- **证据等级**：已观察（步骤 12）
- **用户处境**：用户重复导入同一个文件（或不确定之前导没导过）
- **操作**：再次导入 wechat-sample-real.xlsx
- **看到的反馈**：「导入完成 / 成功导入 0 笔 / 重复跳过 327 笔 / 文件内重复 0 笔 / 已取消 0 笔 / 未匹配分类 167 笔」
- **为什么会卡住**：标题说"导入完成"，正文说 0 笔；且 0 笔新增却仍报"未匹配分类 167 笔"。用户无法判断这是成功还是失败。
- **最小修改**：`import_page.dart` 报告对话框按结果分叉：
  - 新增为 0 时 → 标题「没有新增」，正文首行「这 327 笔之前已经导入过了，没有重复记账」；
  - 「未匹配分类」仅在 `inserted > 0` 时显示。
- **可观察的验收结果**：二次导入看到「没有新增 / 这 327 笔之前已经导入过了，没有重复记账」，无矛盾数字。

### P4【体验摩擦】首页空态没有任何引导

- **维度**：D1 入口可懂
- **证据等级**：已观察（步骤 1）
- **用户处境**：零配置新用户第一次打开首页
- **看到的反馈**：「本月账单」标题下方为一片空白，无"还没有账单"、无"去记一笔"提示。（底栏虽有橙色「记一笔」，但视线焦点所在的列表区是空的且无解释。）
- **最小修改**：`home_page.dart` 列表空态加一行「还没有账单，点下方「记一笔」开始」。
- **可观察的验收结果**：零配置首屏列表区能看到明确的下一步。

### P5【体验摩擦】记一笔的保存按钮在折叠下方，需滚动才发现

- **维度**：D1 入口可懂 / 下一步可见
- **证据等级**：已观察（MuMu 1600×900 横屏；竖屏手机可能不触发）
- **用户处境**：用户在记一笔页填完金额和分类
- **看到的反馈**：首屏只有金额 + 数字键盘 + 分类行，「备注」和「记一笔」保存按钮在折叠下方，上滑后才出现。
- **为什么会卡住**：用户填完必填项后看不到"下一步"，会以为还没填完或按钮不存在。
- **最小修改**：把保存提为 AppBar 右侧文字按钮「保存」（`record_page.dart` 的 `AppBar.actions`），底部按钮保留即可。
- **可观察的验收结果**：任意屏向下，填完金额 + 分类后保存入口无需滚动即可见。

### P6【体验摩擦】预览页看不出如何取消单条

- **维度**：D1 入口可懂
- **证据等级**：已观察（步骤 7）
- **用户处境**：用户在导入预览页想排除某几笔
- **看到的反馈**：列表项可点，但无勾选框、无「取消」字样，点击后的效果不明。
- **最小修改**：列表项右侧加一个默认勾中的 checkbox icon，顶部加一句「点条目可取消，不导入它」。
- **可观察的验收结果**：预览页一眼能看出哪些被选中、点一下是取消。

## 6. 认可已有设计（保持不变）

1. **导入页入口文案精准**：「支持微信 / 支付宝导出的账单文件 / 微信支付 xlsx / CSV，支付宝 CSV（自动识别编码）」——新用户点进去就知道要准备什么、什么格式能过。教科书级，别改。

3. **指纹幂等完全正确**：二次导入 0 新增 / 327 重复跳过，无重复记账。
4. **导入性能**：327 笔 <1s 完成，不需要进度条（D4 不适用，是好事）。
5. **报告数字维度齐全**：成功 / 重复跳过 / 文件内重复 / 已取消 / 未匹配分类，颗粒度够。
6. **持久化正确**：`am force-stop` 后重启，数据完好。
7. **SAF 免权限**：不申请存储权限，直接走系统文件选择器，权限模型干净。
