## 1. 要解决的问题

F7.4 交付的搜索是一个**全屏独立路由**（`/search`），进去后首页被完全遮住：

- 视觉上与「首页为中心」的 App 结构割裂，进去像换了个 App；
- 没有任何筛选入口——想「只看支出」只能靠关键词碰运气（除非分类名恰好叫「支出」）。

## 2. 目标（DoD）

1. 首页 header 搜索图标 → **浮层覆盖在首页之上**（首页仍留在页面栈里、可见于毛玻璃下方），**不再是全屏路由**。
2. 浮层顶部为**不透明提示块**：关闭按钮 + 输入框 + 一键清空 + **筛选建议 chips**（仅支出 / 仅收入 / 转账）。
3. 提示块**以下**为**毛玻璃**（`BackdropFilter` 模糊 + 半透明遮罩），能看见并模糊透出首页内容。
4. 点建议 chip → 词**填入输入框**（可见、可编辑、可一键清空），执行时按**类型筛选**而非文本匹配。
5. 结果列表**浮在玻璃之上**滚动显示（条目自带背景保证可读）。
6. 三种状态齐备：未输入（引导）、无结果（沿用 F7.4 的顶部对齐 + 约 1/5 屏高）、有结果（汇总 + 列表）。
7. 关闭方式：点玻璃区 / 系统返回键 / 提示块左侧关闭按钮。
8. 门禁：`flutter analyze` 0 issue；`flutter test` 全绿（226 + 新增）。

## 4. 设计

### 4.1 浮层实现

用 `showGeneralDialog`，**不新增路由**：

- `barrierDismissible: true` → 点玻璃区即关闭；
- `barrierColor: Colors.transparent` → 遮罩自己画（要毛玻璃，不要纯色）；
- `barrierLabel: '搜索'`（无障碍朗读）；
- `transitionDuration` 短淡入（约 150ms）；
- child 用 `Material(type: MaterialType.transparency)` 包裹，保证文字主题样式生效；
- `ProviderScope` 在最外层，浮层内 `ref` 正常可用；
- 提示块用 `MediaQuery.paddingOf(context).top` 避开状态栏。

**路由处置**：`/search` 路由与 `SearchPage` **一并移除**，文件改名
`search_page.dart` → `search_overlay.dart`（`SearchPage` → `SearchOverlay`）。

> 理由：再留一条独立全屏路由就变成两份 UI + 两套刷新链路。本项目已多次因「同一个东西两份状态」
> 踩坑（统计页不刷新、并行 Edit 丢路由），这里直接砍掉不留后患。

### 4.2 毛玻璃的层次

```
Stack
├─ BackdropFilter(ImageFilter.blur(sigmaX: 12, sigmaY: 12))   ← 铺满全屏
│   └─ Container(color: surface 半透明 ~0.55)
├─ 提示块（不透明卡片，贴顶）                                  ← 盖住玻璃上半部分
└─ 内容区（结果列表 / 引导态 / 无结果态）                       ← 浮在玻璃之上
```

玻璃**铺满全屏**、由不透明的提示块遮住上半部分 → 视觉上等价于「提示块以下才是玻璃」，
但实现比"只给下半屏铺玻璃"简单且不会在提示块边缘出现接缝。

### 4.3 建议词怎么执行（**本次核心待签项**）

按已确认的选择，chip 点击是**把词填进输入框**——不引入独立筛选状态，
好处是条件始终**可见、可编辑、可一键清空**。

但「仅支出 / 仅收入 / 转账」这些字**不在业务字段里**（备注 / 分类名 / 金额都匹配不到），
直接当关键词搜**恒为空**。所以执行时把它们识别为**类型指令**：

| 输入框内容（解析后） | 执行 |
|---|---|
| `仅支出` | 该账本全部 **`type == 'expense'`** 流水 |
| `仅收入` | 该账本全部 **`type == 'income'`** 流水 |
| `转账` | 该账本全部 **`type == 'transfer'`** 流水 |
| `仅支出 餐饮` | `type == 'expense'` **且**命中「餐饮」（类型词剥离后，剩余文本走 F7.4 原口径） |
| 其他 | 完全走 F7.4 原口径（分类名 / 备注 / 金额并集） |

- 类型词**不参与**文本匹配（否则永远搜不到）；解析为纯函数（`parsePlan` / `stripTypeWords`）。
- **类型词须独立成词**（前后为空白 / 串首尾）：`转账手续费` 不会被误判成指令，仍按普通关键词搜；
  代价是单独输入 `转账` 时搜不到「备注里含转账二字」的流水，见 §5 的副作用说明。
- chip 点击填入时**补一个尾随空格**（`仅支出 `）：用户接着敲关键词就是「仅支出 11」，
  有分隔才会被解析成「类型 + 关键词」。真机走查发现不补空格会拼成 `仅支出11` → 不认指令 → 恒为空。
- chip 高亮态**由输入框内容推导**（含「仅支出」→ 该 chip 高亮），保证「填入」与「高亮」永远一致，
  不会出现「chip 亮着但输入框是空的」这种双份状态。
- chip 关掉 `showCheckmark`：默认对勾会让选中 chip 变宽、把后面几个挤位移（真机看出来的跳动）。

### 4.4 转账

`Transactions.type` 支持 `transfer`（此时 `categoryId` 为 NULL），但**记账页没有转账入口**，
现有数据基本不可能出现 `transfer`（除非导入账单解析出来）。本次**保留该 chip**：
点了走类型筛选，命中为空则显示无结果态。

## 5. 不做的（本次范围外）

- **搜索历史**（用户明确说不需要）
- 关键词高亮 / 账户名匹配 / 拼音首字母 / 日期区间筛选（仍留在 `todo-flutter.md` F7.5）
- 类型词与其他关键词的复杂布尔组合（只支持「类型词 + 一段剩余关键词」）
- 记账页新增转账入口（`transfer` 仍然是只读，不写）
- 搜索"备注里含『转账』的流水"（与类型指令冲突，见 §4.3）

## 6. 验收标准

| # | 场景 | 期望 |
|---|---|---|
| 1 | 首页点搜索图标 | 浮层覆盖出现，**首页在毛玻璃下可辨**（不跳页、底栏仍在） |
| 2 | 提示块 | 关闭按钮 + 输入框 + 一键清空 + 三个 chips；背景**不透明** |
| 3 | 提示块以下 | 毛玻璃模糊，能看见首页内容轮廓 |
| 4 | 点「仅支出」 | 词进输入框，结果 = 该账本全部**支出** |
| 5 | 点「仅收入」/「转账」 | 同上，分别 = 全部收入 / 全部转账（可能为空态） |
| 6 | 「仅支出」+ 关键词 | 结果 = 支出 **且**命中关键词 |
| 7 | 一键清空 | 输入框空 + chips 全灭 + 回引导态 |
| 8 | 点玻璃区 / 返回键 | 浮层关闭，回首页（数据无变化） |
| 9 | 无结果 | 沿用顶部对齐 + 约 1/5 屏高提示（F7.4 形态） |
| 10 | 结果条目 | 点=编辑、长按=删除；删改后浮层内列表 + 首页 / 日历 / 统计全刷 |

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | **引导态点提示块以外的空白关不掉浮层**（无结果态却可以） | `_Intro` 当时用 `SingleChildScrollView`，Scrollable 的 `RawGestureDetector` 以 `HitTestBehavior.opaque` 命中整块下方区域，点击传不到底层玻璃的关闭手势 | `_Intro` 改 `Align(topCenter)`——只占内容高度，空白可穿透；内容约 220dp，正常屏放得下 |
| 2 | 选中 chip 出现对勾 → chip 变宽 → **后面几个整排位移** | `ChoiceChip` 默认 `showCheckmark: true` | `showCheckmark: false`，选中态靠底色 / 边框区分 |
| 3 | 点 chip 后接着敲关键词 → **拼成 `仅支出11`，类型指令失效、结果恒为空** | chip 填入的是纯词，与后续输入之间没有分隔符 | chip 填入时补**尾随空格**（`仅支出 `），用户接着敲就是「仅支出 11」 |

> 教训：问题 1、3 都是「widget 测试绿、真机才炸」的类型 —— 前者依赖命中测试的空白穿透，
> 后者依赖「点完 chip 再敲字」这条操作序列。**涉及手势命中与连续输入的操作，必须上真机走一遍。**
