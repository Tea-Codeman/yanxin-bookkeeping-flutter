## 4. 问题清单

### F1（体验摩擦）账户图标 / 颜色无法设置，视觉上无法区分账户

- **用户处境**：有多个账户（现金 / 招行 / 支付宝）时，所有行都是同一个琥珀橙钱包图标
- **操作**：无法操作 —— 界面没有入口
- **看到的反馈**：每行图标完全相同，只能靠文字名称区分
- **为什么会卡住**：不阻断，但账户多了之后扫视成本高；表里 `icon` / `color` 列已存在（schema v1 就有），实现只是没暴露
- **最小修改**：在 `account_form_sheet` 加一行「图标」横向选择（复用 `accountTypeIcon` 的 6 个图标即可，不引入图标库）；`color` 暂不做
- **可观察的验收结果**：选不同图标后，列表行图标随之变化，冷启动后保持不变
- **证据等级**：`已观察`（截图中每行图标一致）

### 非问题（澄清，避免后续误判）

| 现象 | 结论 |
|---|---|
| 点弹窗**上方遮罩区**会关闭弹窗 | **正常设计**。`showModalBottomSheet` 的 barrier 行为与「取消」等价。走查初期曾因坐标推算错误（该页 TextField 无文本时不出现在语义树里）把它误判为"点输入框关窗"的阻断 bug，已用真实坐标复测推翻 |
| 净资产为负显示红色 | **符合预期**。中国习惯：`>= 0` 琥珀橙（品牌色）、`< 0` 红 `#FF6B6B`。资产/支出同屏时颜色语义不冲突（余额负数本就该红） |
| 账户行「收 / 支」小字在 0 流水时也是 `0.00` | 可接受。信息密度换来的确定性，优于空占位 |

## 5. 认可已有设计（保持不变）

1. **开箱即用**：新建账本自动带「现金」账户，资产页首次进入就有真实数据，**没有强制开户向导**（符合 B/C 分类原则）
2. **错误提示就地 + 不丢内容**：校验文案在字段下方，「格式不对」时弹窗不关、已填内容全在
3. **删除保护的前置化**：有流水时**不进入二次确认**而是直接说明原因并给出下一步（「请先把这些流水改到别的账户」），比"删了再报错"好
4. **数据版本号刷新**：记一笔后切到资产页数据已是最新，无需下拉刷新；删除账户后列表与净资产同步更新
5. **空态有引导**：无账户时给出「新建账户」按钮而不是空白
6. **全中文人话**：整个链路零错误码、零技术术语
