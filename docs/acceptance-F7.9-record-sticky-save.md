## 3. 吸底行为（D3）

设备 900×1600 下内容刚好接近一屏，滚动位移不足以证伪 → 改用**改矮视口**（`wm size 900x1000`，

| 指标 | 矮视口下的值 |
|---|---|
| 吸底按钮 | `[可点] 记一笔 @(450,928)` → **视口内**（928 < 1000） |

| 截图 | `05-short.png`：键盘格子在吸底栏上方被裁切，吸底栏稳贴底部、描边清晰 |

- **D3 ✅ 内容被挤出视口，按钮留在原位** —— 这正是本方案要解决的原始痛点：
  改造前按钮在滚动内容末尾，矮视口 / 大屏 / 横屏下它会在 y≈1400（**视口外**），
  用户必须滚动才能保存；现在恒定落在 body 底部。

## 4. 键盘场景（D4）—— ⚠️ 未能直接验证

- MuMu 12 接了硬件键盘映射 → Flutter 判定「有物理键盘」→ **不弹软键盘**；
  强制 `settings put secure show_ime_with_hard_keyboard 1` 后重启聚焦**仍然不弹**
  （语义树里按钮仍在 `@1528`，布局零变化）。
- **等价验证已做**：键盘弹起对布局的作用 = `MediaQuery.viewInsets.bottom > 0` → Scaffold 压缩 **body**；
  而「改矮视口」同样是压缩 body 可用高度（§3 已验证吸底栏跟着落到底部、不被内容挤走）。
  差别只在：真实键盘还会让 `Scaffold` 把 body 上移到底部 inset 之上 —— 这正是本方案
  **把吸底栏放进 body 而不用 `Scaffold.bottomNavigationBar`** 的原因（后者不随键盘上移，会被键盘盖住）。
- **结论**：机制上成立、等价场景通过；但**软键盘弹起这一真实场景本机测不了** →
  **建议用户在自己的真机（Redmi K50）上试一次**：进记一笔 → 点备注 → 弹键盘 → 看底部按钮是否在键盘上方。

## 8. 构建与核验命令（复现用）

```bash
source env.sh
python tool/build_kernel_fallback.py                    # 产 kernel_blob.bin
( cd android && ./gradlew assembleDebug -x compileFlutterBuildDebug )
python tool/verify_apk_kernel.py                        # APK 内 kernel sha256 与盘上比对
adb -s emulator-5554 install -r build/app/outputs/flutter-apk/app-debug.apk
```

⚠️ **本机 adb 每次新 shell 都会重启 daemon**（沙箱杀进程）→ 一条命令序列开头要先
`adb start-server` + `sleep 2~3`，否则首条 `adb` 命令会撞 `device offline`。
